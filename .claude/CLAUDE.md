# 인테리어 견적 시스템 - 에이전트 팀

## 팀 구성

| 에이전트 | 파일 | 역할 |
|---------|------|------|
| 디자이너 | `.claude/agents/designer.md` | UI/UX, 스타일, 고객 경험 |
| 개발자 | `.claude/agents/developer.md` | 프론트+백엔드 코드 구현 |
| QA | `.claude/agents/qa.md` | 테스트, 버그 찾기, 검증 |
| PM | `.claude/agents/pm.md` | 전체 조율, 우선순위, 진행 관리 |
| 마케터 | `.claude/agents/marketer.md` | SEO + 카피라이팅 (보조, sonnet) |
| 인테리어 실장 | `.claude/agents/interior_expert.md` | 공정/자재/단가 도메인 검증 (보조) |

## 사용법

새 채팅에서 에이전트를 불러서 사용:
```
디자이너 에이전트: 설문 랜딩 페이지의 스타일/톤 선택 UI를 개선해줘
개발자 에이전트: submitSurvey 성능을 5초 이하로 최적화해줘
QA 에이전트: 설문 전체 플로우를 테스트하고 버그 리포트해줘
PM 에이전트: 다음 주 작업 우선순위를 정리해줘
인테리어 실장 에이전트: 현재 견적 엔진의 단가가 현실적인지 검토해줘
```

## 워크플로우
1. PM이 요구사항 정리 + 태스크 분배
2. **인테리어 실장이 도메인 요구사항 검토** (공정/단가/현실성)
3. 디자이너가 UI 설계 (컴포넌트 수정)
4. 개발자가 로직 구현 (API, 엔진, 배포)
5. QA가 빌드 검증 + 플로우 테스트
6. PM이 최종 승인

## 주요 규칙
- 한국어로 소통
- 사용자는 개발자가 아님 — 기술 용어 최소화
- 비용 0원 유지 (GAS + CF Pages 무료)
- 수정 후 반드시 빌드 확인 (`npm run build`)
- Git push 전 TypeScript 에러 0 확인

## ⚠️ Google 계정 보호 규칙 (필수)

이전에 브라우저 자동화 + 반복 API 호출로 Google 계정이 정지된 적이 있음.
자동화는 허용하되, 실패 시 백오프 규칙을 적용할 것.

### 기본 원칙: 자동화 OK, 폭주 NO
- Google 서비스(시트, 드라이브, Apps Script) 자동 조작 **가능**
- 단, 아래 보호 규칙을 반드시 적용

### 호출 제한 규칙
1. **Google 서비스 호출 간격**: 최소 3초 대기
2. **같은 작업 실패 시 백오프**:
   - 1회 실패 → 10초 대기 후 재시도
   - 2회 연속 실패 → 30초 대기
   - 3회 연속 실패 → **중단하고 사용자에게 보고** (직접 해달라고 요청)
3. **세션당 Google API 호출 상한**: 50회 (초과 시 사용자 확인 후 계속)
4. **크롤링 속도**: 요청 간 3~5초 딜레이, 세션당 100건 이하

### 우선 순위: CLI > API > 브라우저
- **1순위 (가장 안전)**: clasp push/deploy, curl로 GAS API 호출
- **2순위**: 브라우저에서 Google 시트/에디터 조작
- **3순위 (최후 수단)**: gviz CSV 반복 조회

같은 작업을 할 수 있다면 1순위 방법을 먼저 시도할 것.
브라우저 조작은 CLI로 안 될 때만 사용.

### 실패 감지 신호
아래 상황이 발생하면 즉시 Google 호출을 중단:
- 403/429 에러 (속도 제한)
- "이 작업을 수행할 수 없습니다" 류 메시지
- 페이지가 CAPTCHA/인증을 요구
- 연속 3회 타임아웃
